# Calendar 기준 로컬 통합 및 화이트박스 QA

## 작업 기준

- 기준 브랜치: `feature/calendar-places-sharing` (대화에서 Calendar로 지칭)
- 기준 커밋: `d4fcb0eb96e3b7c40ac61c2902fa9fcff125f6d6`
- 비교·통합 대상: `norefactor/new-section`의 추가 기능을 현재 Calendar 모듈 구조에 맞게 반영했습니다. `main`, `feature/folder-timetable`, `prototype`, `refactor/split-modules`의 중복·이전 구현으로 Calendar 기능을 되돌리지 않았습니다.
- 초기 통합과 QA는 로컬 작업 브랜치 `integration/calendar-features`에서 수행했습니다.
- 후속 main 통합에서는 아래 브랜치들의 이력을 부모 커밋으로 보존하고, 이 문서에 명시한 기능만 Calendar 구조에 반영합니다. 테스트용 자료와 개인 데이터는 커밋에서 제외합니다.

## 반영한 기능

| 기능 | 통합 결과 |
| --- | --- |
| 학기별 실제 자료 폴더 분리 | `data/buildings/건물명/학기/강의명` 사용. 같은 강의명도 학기가 다르면 분리합니다. |
| 지도 일정 번호에서 과목 자료 열기 | 일정 번호를 클릭하면 해당 수업 자료함을 엽니다. 같은 장소의 일정이 여러 개면 선택 목록을 표시하며, 수업이 아닌 일정은 장소 자료함으로 연결합니다. |
| 과목 카드에 파일 드롭 | 선택 학기·과목 폴더로 파일을 이동합니다. 기존 파일 작업·이름 충돌 처리·실행 취소 기능을 재사용합니다. |
| 일일 일정의 시·분 선택 | 기존 `TimePicker`를 재사용합니다. 종료 24:00, 가져온 5분 단위 외 시각 보존, 시작·종료 시각 검증을 유지합니다. |
| Windows 실행 파일과 ZIP | `package.ps1`에서 소스 컴파일, 지도 포함 JAR, 최소 Java 런타임, EXE, ZIP을 생성합니다. 개인 일정·자료는 포함하지 않습니다. |

요청에 따라 **과거 날짜에서 새 일정 추가 시 오늘로 보정**과 **별도 하루 전체 시간표 화면**은 추가하지 않았습니다. 과거 날짜는 선택한 날짜 그대로 저장되는지 검사했습니다.

## 기존 자료 보존

기존 `건물명/강의명` 구조에서 새 학기 구조로 전환할 때 원본과 `data/.folder-course-backups`의 복구 사본을 보존합니다. 여러 학기가 같은 기존 폴더를 사용했다면 각각 복사합니다. 같은 이름의 다른 파일은 번호를 붙여 둘 다 보존하며, 동일한 마이그레이션을 다시 실행해도 같은 파일을 중복 복사하지 않습니다.

수업의 이름·건물 변경은 해당 학기 폴더에만 적용합니다. 같은 폴더를 쓰는 다른 수업이 남으면 원본을 보존합니다. 수업 삭제로 실제 자료를 지우지 않습니다.
